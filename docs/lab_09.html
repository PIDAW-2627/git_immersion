lab 9 Cambios, no archivos

Objetivos

  • Aprender que git trabaja con cambios, no con archivos.

La mayoría de los sistemas de control de versiones trabajan con archivos. Añades un archivo al control de versiones y el sistema registra los cambios en ese archivo a partir de ese momento.

Git se centra en los cambios de un archivo, más que en el archivo en sí. Cuando escribes git add file, no le estás diciendo a git que añada el archivo al repositorio. Lo que le dices es que tome nota del estado actual de ese archivo para incluirlo más adelante en un commit.

En este lab intentaremos explorar esa diferencia.

Primer cambio: permitir un nombre por defecto

Modifica el programa “Hello, World” para que tenga un valor por defecto si no se le pasa ningún argumento en la línea de comandos.

hello.py

import sys

name = sys.argv[1] if len(sys.argv) > 1 else "World"

print(f"Hello, {name}!")

Añade este cambio

Ahora añade este cambio al área de preparación (staging) de git.

Ejecuta:

git add hello.py

Segundo cambio: añadir un comentario

Ahora añade un comentario al programa “Hello, World”.

hello.py

import sys

# Default is "World"
name = sys.argv[1] if len(sys.argv) > 1 else "World"

print(f"Hello, {name}!")

Comprueba el estado actual

Ejecuta:

git status

Deberías ver…

Salida:

$ git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   hello.py

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   hello.py

Fíjate en que hello.py aparece dos veces en el estado. El primer cambio (añadir un valor por defecto) está preparado y listo para el commit. El segundo cambio (añadir un comentario) no está preparado. Si hicieras commit ahora mismo, el comentario no se guardaría en el repositorio.

Vamos a probarlo.

Hacer commit

Haz commit del cambio preparado (el valor por defecto) y vuelve a comprobar el estado.

Ejecuta:

git commit -m "Added a default value"
git status

Deberías ver…

Salida:

$ git commit -m "Added a default value"
[main 15d9d4e] Added a default value
 1 file changed, 3 insertions(+), 1 deletion(-)
$ git status
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   hello.py

no changes added to commit (use "git add" and/or "git commit -a")

El comando status te indica que hello.py tiene cambios sin registrar, pero ya no está en el área de preparación.

Añade el segundo cambio

Ahora añade el segundo cambio al área de preparación y ejecuta git status.

Ejecuta:

git add .
git status

Nota: Hemos usado el directorio actual (‘.’) como el archivo que añadir. Es un atajo muy cómodo para añadir todos los cambios de los archivos del directorio actual y de sus subdirectorios. Pero, como lo añade todo, es muy buena idea comprobar el estado antes de hacer un add ., para asegurarte de que no añades ningún archivo que no querías.

Quería que conocieras el truco de “add .”, pero en el resto del tutorial seguiremos añadiendo los archivos de forma explícita, por seguridad.

Deberías ver…

Salida:

$ git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   hello.py

Ahora el segundo cambio está preparado y listo para el commit.

Haz commit del segundo cambio

Ejecuta:

git commit -m "Added a comment"
