lab 34 Hacer rebase

Objetivos

  • Usar el comando rebase en lugar del comando merge.

Bien, hemos vuelto a un momento anterior a la primera fusión y queremos llevar los cambios de main a nuestra rama greet.

Esta vez usaremos el comando rebase en lugar del comando merge para traer los cambios de la rama main.

Ejecuta:

git checkout greet
git rebase main
git hist

Salida:

$ git checkout greet
Switched to branch 'greet'
$
$ git rebase main
First, rewinding head to replay your work on top of it...
Applying: added Greeter class

Applying: updated Rakefile
$
$ git hist

Merge VS rebase

El resultado final del rebase es muy parecido al de la fusión. La rama greet contiene ahora todos sus cambios, además de todos los cambios de la rama main. Sin embargo, el árbol de commits es bastante distinto. El árbol de commits de la rama greet se ha reescrito de forma que la rama main forma parte del historial de commits. Así la cadena de commits queda lineal y es mucho más fácil de leer.

¿Cuándo hacer rebase y cuándo fusionar?

No uses rebase…

  1. Si la rama es pública y está compartida con otras personas. Reescribir ramas compartidas públicamente suele causar problemas al resto del equipo.
  2. Cuando el historial exacto de la rama de commits es importante (ya que rebase reescribe el historial de commits).

Siguiendo estas pautas, yo suelo usar rebase para ramas locales de vida corta y fusionar para las ramas del repositorio público.
